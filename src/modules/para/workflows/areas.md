# Areas

An area represents an enduring responsibility or life context without a defined
completion state. Create one only when no existing area fits and the separation
improves clarity. Time-bounded outcomes belong to projects.

Each area may have a dashboard and durable area documentation. Use registered
area values, configured metadata, and instance paths. Keep dashboards as views;
they do not replace canonical content. Update areas instead of duplicating them,
and archive them only when their active relevance has permanently ended.

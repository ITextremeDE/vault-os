# Tag conventions

Tags complement structure; they do not replace explicit fields, relationships,
or a clear folder model.

## Rules

- Use Obsidian-compatible tags without spaces.
- Use a single documented spelling for each tag.
- Prefer descriptive compound words over abbreviations.
- Keep tag syntax distinct from controlled values defined by schemas and
  registers.

Examples:

- `KnowledgeManagement`
- `SecondBrain`
- `ProjectDelivery`

An instance or module may adopt a stricter convention, but it must document the
rule in one canonical place.

# Vault-OS 0.1.0 release validation

- Date: 2026-08-12
- Package: `0.1.0`
- Verdict: Passed locally
- Scope: repository checkout and temporary vaults only

## Automated acceptance

The complete documented acceptance suite passed:

- 61 unit and integration tests;
- portability validation for 149 distributable files and 19 manifests;
- portability-matrix validation for 119 classified source files;
- manifest validation for 25 core files, 101 files in 14 modules, 11 instance
  seeds, and one runtime artifact; and
- `git diff --check`.

## Release upgrade

A temporary vault was installed from repository commit `92db745` with package
`0.1.0-dev.13`, all 14 optional modules, bootstrap files, and the Codex provider
adapter. Its initial `doctor --ai` result was healthy.

The release candidate then upgraded that vault to `0.1.0`. The lifecycle
verified 104 unchanged managed files, preserved all 11 instance files, updated
only device-local release metadata, and finished with a healthy `doctor --ai`
result.

## Synchronized-device boundary

The upgraded primary vault was transferred to a temporary secondary vault while
excluding the documented device-local `.vault-os/`, `.agents/`, `.claude/`,
`.codex/`, `.qmd/`, and `.mcp.json` paths. `device-sync` reconstructed the local
`0.1.0` release lock after verifying all 104 managed files and 11 instance
files. A checksum snapshot confirmed that no synchronized file changed.

Local `agent-init --provider codex` recreated provider discovery on the
secondary device, and `doctor --ai` reported the installation healthy.

## Executed AI client

Codex CLI `0.147.0-alpha.6.5` ran as an ephemeral read-only session in the
secondary vault. It read the shared instructions, release lock, and a generated
skill wrapper and returned:

```text
release=0.1.0
instruction=AGENTS.md
skill=.agents/skills/vault-search/SKILL.md
```

A complete before-and-after checksum snapshot confirmed that the session did
not change the vault. Host-local Codex session-database warnings were unrelated
to the generated Vault-OS installation and did not affect the result.

## Not executed

- Claude Code was not available on `PATH`; its adapter remains covered by the
  automated structural and lifecycle tests.
- QMD was not available on `PATH`; its configuration, merge, and conflict
  contracts remain covered by automated tests.
- Obsidian Sync itself was not invoked; the transfer reproduced its documented
  file boundary and excluded every device-local path.
- No real vault, private vault content, or `.obsidian` directory was read or
  modified.

The release tag is accepted for publication only when the release commit also
passes GitHub Acceptance and the same annotated tag resolves to that exact
commit on GitHub and Forgejo.

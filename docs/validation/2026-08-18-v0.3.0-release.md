# Vault-OS 0.3.0 release validation

- Date: 2026-08-18
- Package: `0.3.0`
- Verdict: Passed
- Scope: automated acceptance, isolated lifecycle upgrade, synchronized-device
  boundary, GitHub Acceptance, and fresh public-tag validation

## Automated acceptance

The complete documented acceptance suite passed:

- 66 unit and integration tests;
- portability validation for 151 distributable files and 19 manifests;
- portability-matrix validation for 119 classified source files;
- manifest validation for 25 core files, 111 files in 14 modules, 11 instance
  seeds, and one runtime artifact; and
- `git diff --check`.

The tests include German template closing-block checks and both text and
Wiki-link area representations, including materialized PARA dashboard queries
and invalid representation handling.

GitHub Acceptance passed for the release commit on Python 3.10 and Python 3.14.

## Release upgrade

An isolated temporary vault was installed from the public `v0.2.0` package with
all 14 optional modules. The `0.3.0` release candidate upgraded the installation,
updated three changed managed core files, verified 106 unchanged managed files,
preserved all 11 instance files, and finished with a healthy `doctor` result.

## Synchronized-device boundary

The upgraded primary vault was transferred to a temporary secondary vault while
excluding the documented device-local `.vault-os/`, `.agents/`, `.claude/`,
`.codex/`, `.qmd/`, and `.mcp.json` paths. `device-sync` reconstructed the local
`0.3.0` release lock after verifying all 109 managed files and 11 instance files.
Both the primary and secondary `doctor` checks reported zero errors and zero
warnings. A checksum comparison confirmed that `device-sync` changed no
synchronized file.

## Fresh public-tag verification

The public `v0.3.0` tag was cloned into a new temporary directory after
publication. Its manifest version and changelog heading matched the tag. The
complete acceptance suite passed again, and a clean vault installation with all
14 modules finished with a healthy `doctor` result.

The annotated `v0.3.0` tag resolves to release commit
`9171843dc524c52a3d682f6b6530660453876bf6` on GitHub and the Forgejo mirror,
and the GitHub release is published for that tag.

## Boundaries and skipped clients

- No production vault or `.obsidian` directory was read or modified.
- Codex and Claude Code clients were not exercised directly; their adapters
  remain covered by the automated structural and lifecycle tests.

# Naming

Names should remain clear, readable, stable, and maintainable.

## Core rules

- Prefer descriptive domain language over technical abbreviations.
- Preserve an established consistent spelling unless a migration has a clear
  benefit.
- Avoid prefixes, numbering, and identifiers without a structural purpose.
- Use special characters sparingly and follow the configured vault language.
- Folder names follow the same clarity rules as filenames.

`README.md` is reserved for folder and repository overviews. Modules may define
additional naming patterns for their own content kinds, dashboards, and
periodic notes. Those patterns must remain in the owning module rather than the
core.

Renaming requires checking links, automation, and migration cost. A stylistic
preference alone is not sufficient reason.

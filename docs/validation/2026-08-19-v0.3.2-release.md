# Vault-OS 0.3.2 release validation

- Date: 2026-08-19
- Package: `0.3.2`
- Verdict: Passed
- Scope: automated acceptance, isolated lifecycle upgrade, and
  synchronized-device boundary

## Automated acceptance

The complete documented acceptance suite passed:

- 66 unit and integration tests;
- portability validation for 151 distributable files and 19 manifests;
- portability-matrix validation for 119 classified source files;
- manifest validation for 25 core files, 111 files in 14 modules, 11 instance
  seeds, and one runtime artifact; and
- `git diff --check`.

Regression assertions verify that the materialized review queue excludes both
the configured system tree and the visible `Vault-OS` instance directory with
recursive `file.inFolder()` predicates.

## Release upgrade

An isolated temporary vault was installed from the public `v0.3.1` package with
all 14 optional modules. The `0.3.2` release candidate upgraded the
installation, updated the managed review view, verified 108 unchanged managed
files, preserved all 11 instance files, and finished with a healthy `doctor`
result.

## Synchronized-device boundary

The upgraded primary vault was transferred to a temporary secondary vault while
excluding the documented device-local `.vault-os/`, `.agents/`, `.claude/`,
`.codex/`, `.qmd/`, and `.mcp.json` paths. `device-sync` reconstructed the local
`0.3.2` release lock after verifying all 109 managed files and 11 instance
files. Both the primary and secondary `doctor` checks reported zero errors and
zero warnings. A checksum comparison confirmed that `device-sync` changed no
synchronized file.

## Boundaries and skipped clients

- No production vault or `.obsidian` directory was modified during release
  validation.
- Obsidian rendering was reserved for the authorized post-release MindOS
  verification.
- Codex and Claude Code clients were not exercised directly; their adapters
  remain covered by the automated structural and lifecycle tests.
